# Databricks RetailX Migration – End-to-End Pipeline

## Overview

This project demonstrates an end-to-end data pipeline built on Databricks to simulate migration from Oracle to a Lakehouse architecture.

The pipeline implements:

* Unity Catalog governance
* Bronze, Silver, Gold architecture
* Delta Live Tables pipeline
* Data quality validation
* Oracle SQL migration using Lakebridge tools
* External ingestion workflow

---

## Architecture

Oracle Scripts (SQL, PL/SQL)
→ Data Landing (Fivetran)
→ Bronze Layer
→ Silver Layer (Cleansed & validated)
→ Gold Layer (Aggregated business metrics)

### Task D – Delta Live Tables Pipeline

A Delta Live Tables (DLT) pipeline was implemented to automate ingestion, transformation, and validation across the Medallion architecture.

The pipeline performs the following steps:

* Reads raw data from Bronze tables
* Applies cleansing and normalization to create Silver tables
* Generates Gold tables containing business-level aggregations
* Applies expectations and validation rules to monitor data quality

Validation rules implemented in the pipeline include:

* Non-null checks on key fields
* Positive value checks for numeric measures
* Valid categorical value enforcement
* Threshold-based validation for business limits

The pipeline was executed in **Triggered mode**, processing available data in batch runs.

---

### Task E – Data Quality Checks

Data quality validation was implemented at the Silver layer to ensure reliability before aggregation.

The following checks were applied:

Null Checks
* Mandatory columns were validated to ensure required fields were present.

Datatype Validation
* Numeric fields were cleaned and cast to appropriate data types.
* Date fields were standardized and converted to valid formats.

Pattern Validation
* Email addresses were validated using regex rules.
* Phone numbers and pincodes were validated for correct length and format.

Outlier Detection
* Business thresholds were applied to identify and filter unrealistic values.
* Date range checks were applied to ensure valid time periods.

Records failing validation were filtered during transformation so that only clean, reliable data progressed to downstream layers.

## Assumptions

* Oracle database connectivity was simulated using sample SQL, PL/SQL, and CSV files.
* A small dataset was used to demonstrate pipeline functionality.
* The environment was single-user; therefore, role-based access controls were not implemented.
* Delta Live Tables pipeline was executed in Triggered mode for batch processing.
* Data files were ingested after landing in external storage via Fivetran.
* The project focuses on pipeline design and data quality implementation rather than production-scale deployment.
